# Contributing

Bug reports, protocol corner cases and pull requests are welcome.

## Development setup

```bash
git clone https://github.com/Mhrnqaruni/openvpn-cert-inspector
cd openvpn-cert-inspector
python -m venv .venv && . .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -e ".[dev,figures]"
pytest
ruff check . && ruff format --check .
```

## Tests

- `tests/` runs anywhere: it uses an in-process OpenVPN control-channel server
  (`tests/fakeserver.py`) and throw-away certificates (`lab/pki.py`).
- `lab/run_lab.py` needs Linux, the `openvpn` binary and permission to create
  TUN devices. It starts real OpenVPN servers and clients. CI runs it on every
  push; locally it runs in the Docker image in `lab/Dockerfile`.

A change to verification behaviour should come with:

1. a unit test in `tests/test_certs.py`;
2. a lab case in `lab/run_lab.py` that shows real clients agree;
3. an update to `docs/compatibility.md` if the client model changes.

## Guidelines

- Keep the runtime dependency set to `cryptography` and the standard library.
- Never log, print or serialise key material. `StaticKey` already redacts
  itself in `repr()`.
- The probe must stay handshake-only: no change may make it send credentials
  or the key-method-2 message.
- Figures are generated by `tools/make_figures.py` from data in `results/`.
  Do not edit SVGs by hand.

## Releases

Bump `src/ovpncert/__init__.py`, add a `CHANGELOG.md` entry, update
`CITATION.cff`, then push a `vX.Y.Z` tag. The release workflow builds and
attaches the wheel and the source distribution.
